How Tijori protects your data

This page says what Tijori does, with the real algorithms, and what it does not do. Tijori is not open source and has not had an independent security audit, so read this as the author's description, and ask if anything is unclear.

The whole picture

Read it from the top. Your password and your fingerprint each open a locked copy of one master key. Everything else comes from that key.

What is encrypted

  • The database (names, document numbers, dates, notes) is encrypted with SQLCipher 4, through SQLite3MultipleCiphers. Temporary tables stay in memory, never in temporary files.
  • Every scanned page and photo is encrypted on its own with AES-256-GCM, using a random nonce and tied to the file's own id. Changing a single byte of a stored file makes it fail to open.
  • Pages you view are decrypted in memory. Any temporary copy is cleared each time the app starts.

Keys, in plain words

  • When you set up the vault, Tijori makes one random 256-bit master key from the phone's secure random generator. Your documents are never locked with your password directly.
  • The database key and the file key are both derived from the master key with HKDF-SHA256, each with its own label.
  • The master key is kept in two locked forms: one opened by your Vault Password, and one held by the Android Keystore that needs your fingerprint or screen lock to open. The everyday unlock uses the second.
  • Changing your password only re-locks the master key. Your documents are not re-encrypted.

How your password becomes a key

The Vault Password goes through Argon2id (64 MiB of memory, 3 passes, a random 16-byte salt) to make the key that unlocks the master key. Argon2id is deliberately slow and memory-hungry, so every guess costs an attacker real work. The settings are stored with the data, so they can be raised in a future version without locking you out. Tijori uses the open-source cryptography package for these algorithms and does not invent its own.

Backups

  • A backup is one file, encrypted with a key made from the password you choose (Argon2id again) and AES-256-GCM, in 64 KiB pieces. Each piece is numbered, the last one is marked as the last, and all pieces are tied to the file's header. A file with a piece changed, removed, moved, added or copied from another backup is refused.
  • Tijori re-reads the backup after writing it and checks every piece before it says the backup worked.
  • A backup is only as strong as its password. When you choose a separate backup password, Tijori refuses easy-to-guess ones.

What leaves your phone

  • Nothing, unless you send it. There is no account, no server, no ads and no analytics.
  • The one network use is a once-a-day check for a new version on GitHub, which you can switch off in Settings.
  • When you install an update, Tijori checks the file's fingerprint. The next version (1.0.3) also checks that the file has Tijori's package name and is signed by the same developer key as the app you have, before it opens the installer. Android applies its own signature check as well.
  • When you share a document, the shared copy is not encrypted. Tijori warns you first. A card's CVV is never shared.
  • Screenshots and the recent-apps preview are blocked inside the app. Copied numbers clear from the clipboard after the time you choose, and the vault locks after the time you choose.

What Tijori does not protect against

  • Someone holding your unlocked phone, or watching you type your password.
  • Malware or a rooted phone. Software that can read other apps' memory can see keys while the vault is open. Encryption on disk cannot stop that.
  • A weak password. If someone gets a copy of your vault or a backup file, the password is the only thing between them and your data, and they can keep guessing offline. Use a long passphrase.
  • Forgetting your password. Nobody can recover the data, including the author. Keep a backup.
  • Documents you share, and anything you copy and paste elsewhere.

Honest status

  • The encryption uses standard, widely reviewed algorithms through well-known libraries. That does not make the app free of mistakes.
  • Tijori has not had an independent security audit, and the source code is not public.
  • Found something? Please report it through GitHub issues, without posting any real document or number.
